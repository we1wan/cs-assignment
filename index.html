Q1 ; explain what is serverless architecture

serverless architecture (or FaaS) is a execution model where developers build and run apps without having to manage and take care about physical or virtual servers, because cloud provider usually automatically takes care of all those things.

the code is ran only in response to triggers (like http api request or file upload), it scales automatically depending on the traffic, and you pay only for what you use.

example; image processing pipeline where you upload a photo to a cloud storage which triggers the serverless function that resizes the image and shuts down automatically after you're done.

Q2 ; describe what is kubernetes and their alternatives

kubernetes is an open source container platform originally made by google, that automates deployment, scaling, networking, (and other things) of containerised applications across multiple host machines(?). it automatically restarts failed containers and adjusts running instances based on usage, so it's also highly avaliable.

popular alternatives are dockerswarm, csc rahti, and hashicorp nomad(?)

Q3 ; possible information security risks when using third party containers

vunerabilities in base images >> public images often have outdated operating system packages and libraries that attackers can exploit to gain access to the container

malicious or tampered images >> attackers can upload evil images containing malware, cryptominers or backdoors in form of typosquatting to trick users

exposed secrets >> some developers hardcode api keys, passwords, or certificates into public container layers, which makes them accessible to anyone pulling the image

Q4 ; what virtualisation platform would i use and why

if i needed to run virtualised windows os on my laptop, i would probably decide based on the primary os of the host laptop

if it uses windows host i would go for microsoft hyper-v >> built directly into windows with native system integration, good performance and efficient cpu and ram resource management + no need for extra software installation

if it uses linux i would go for kvm with qemu >> kvm is directly in linux kernel, combined with virt-manager it's close to native cpu and gpu speed

if it uses macos i would go for oracle virtualbox >> virtualbox is free, open source and runs the same on windows, linux, and macos. it's pretty easy to use and it makes setting everything up and sharing files between host and windows quick and simple
