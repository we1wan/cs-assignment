Q1 ; describe reasons why most companies use cloud based email and calendar services

before, companies were hosting and managing their own email servers on physical hardwares from server rooms. nowadays almost everyone uses cloud services like google workspace or microsoft 365 because maintaining local servers is more risky and expensive.

main reasons in my opinion would be that they dont have to purchase, maintain, or upgrade physical servers (which is also expensive), because cloud email is managed entirely by the provider removing the need for hardware maintenance or manual server updates.

another reason would be that in case of power outage, internet failure or other 'disaster', local servers crash completely. cloud services stay up because theyre distributed between multiple data centers.

example; if a company relies on a email server, and the server room experiences a power outage or ransomware attack, all of the internal and client communications stop until the issue is fixed. with cloud email service, employees can simply use their personal devices to continue the communications without missing anything important.

Q2 ; 2 amazon data leaks and s3 bucket search engines

the most common causes of massive data breaches are usually misconfigured cloud storage buckets. because amazons s3 buckets are private by default, almost every leak has usually happened because admin manually misconfigured bucket permissions to allow public access or applied very loose acl (access control list)

#1 accenture data leak in 2017 | accenture left four aws s3 storage buckets completely public on the internet without any passwords or authentication needed. what happened was that the engineers configured the buckets to be publicly downloadable. the leak exposed around 140gb of highly sensitive data including api keys, identity credentials, and more. anyone who found the bucket url could download the master access keys to accentures internal cloud infrastructure

#2 us military intelligence leak in 2017 | defence contractor booz allen hamilton left unencrypted s3 bucket containing top secret us military national geospatial-intelligence agency credentials exposed to the public. the administrator set the buckets permissions to allow public read access without requiring aws login. bucket had over 60,000 files inside, including ssh keys, raw credentials, and encrypted passwords belonging to the us military intelligence personnel.

some bucket search engines and reconnaissance tools are usually used to scan the web and brute force predict the s3 bucket names, because the urls can get pretty predictable. most common are grayhatwarfare, slurp, awsbucketdump, and bucket finder

Q3 ; my thoughts about when to maintain my own server and when to use saas/paas/iaas

i would maintain my own server if i were to handle some very sensitive data, like government, military, or healthcare data, where local regulations prohibit cloud hosting outside physical borders or mandate direct control over physicial hardware. another reason could be if i were to run specialisied custom hardware devices that cant be virtualised or run in the cloud environments.

iaas would be the best if i needed custom server configs, specific os dependencies, or full root access to install custom software without the hassle of managing my own physical server hardware.

paas would be the best if i wanted to focus primarily on writing application code and deploying quickly without spending time configuring web servers, firewalls, or linux updates.

saas would be the best if a standard application already solves my business problem completely.

the best hierarchy would be saas > paas > iaas > self hosted!

Q4 ; describe why iot devices use googles 8.8.8.8 or other public dns resolvers

many of the smart devices ignore local network settings and use hardcoded dns servers like googles 8.8.8.8 or cloudflares 1.1.1.1 for a few reasons. the main one would be that local isp dns servers often go down, lag, or time out. if a smart tv relied on not always working isp server, it would mark itself offline and the customers would complain. public dns servers run on massive global networks and are almost never down.

another reason would be that smart tvs send a lot of telemetry, usage stats, and ads. manufacturers hardcode public dns so that tracking or streaming endpoints cant be that easily blocked by local tool networks like pihole. home routers also often have very aggressive firewalls or parental control filters which block specific domains. public dns ensures that the device can update its firmware and work without getting blocked by the local router rules.

downsides however, are that every website you open gets sent directly to google/cloudflare, so you kinda lose privacy. public dns also doesnt always pass local location data to cdn, which can sometimes route video streams to a farther slower server.
